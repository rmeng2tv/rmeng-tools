## 1. 핵심 개념 & 제약사항 (가장 중요)

- **WebView 방식**: 기존 React/Vue 웹 서비스를 미니앱으로 실행. 우리 견적서 툴이 여기 해당.
- ❌ **iframe·외부 URL 연결 금지**: `tools.rmeng2.co.kr`를 그대로 불러오는 방식은 정책 위반.
  프론트엔드 소스코드는 **토스 인프라에 배포**해야 함 (`.ait` 빌드 → 콘솔 업로드). 자체 서버와 HTTPS 통신은 가능.
- ❌ **구글 애드센스 작동 안 함**: 토스 웹뷰 안에서는 애드센스 불가 → 수익화는 **토스 인앱광고/인앱결제**로.
- **http는 샌드박스에서만**: 라이브는 https만. http 기반 기능은 샌드박스에서만 정상 동작.
- **서드파티 쿠키 차단(iOS 13.4+)**: 쿠키 기반 로그인 X → 토큰 기반 인증 써야 함. (견적서 툴은 로그인 없어서 무관)
- **TDS(토스 디자인 시스템)는 선택**: 우리는 안 씀. 기존 UI 그대로 유지.

## 2. 프로젝트 구조 (우리 방식: 같은 레포 통합)

- 웹용/토스용을 **한 레포에서** 관리. 분기는 **플래그 1개**:
  ```js
  const IS_TOSS = import.meta.env.MODE === 'toss';
  ```
- 토스 빌드는 `vite --mode toss`로 실행되어 `MODE === 'toss'`가 됨 (granite.config.ts에 지정).
- 웹 빌드(`vite build`, 기본 production 모드)는 `IS_TOSS === false` → **기존과 100% 동일 동작**.
- 현재 토스 전용 분기: `src/main.jsx`의 카카오톡 리다이렉트를 토스 빌드에서만 제외.

## 3. 1회성 셋업 (이미 완료, 새 프로젝트 때 참고)

```bash
# 1) SDK 설치 (React 19 그대로 호환됨. 18로 낮출 필요 없음)
npm install @apps-in-toss/web-framework

# 2) granite.config.ts 직접 작성  ← ait init은 템플릿 스캐폴딩이라 기존 프로젝트엔 위험. 수동 작성 권장.
```

`granite.config.ts` 핵심 형태:
```ts
import { defineConfig } from '@apps-in-toss/web-framework/config';

export default defineConfig({
  appName: 'rmeng-quote',
  appType: 'general',                 // 비게임
  brand: {
    displayName: '알맹이 견적서 메이커',
    primaryColor: '#2563eb',
    icon: '',                          // 콘솔에 로고 업로드 후 이미지 URL 입력
  },
  web: {
    host: 'localhost',
    port: 5173,
    commands: { dev: 'vite --mode toss', build: 'vite build --mode toss' },
  },
  permissions: [],                     // 카메라/위치/사진 등 필요 권한만 추가
  outdir: 'dist',
});
```

- `vite.config.js`는 **안 건드려도 됨** — `ait build`가 토스 플러그인을 내부 적용.
- `.gitignore`에 빌드 부산물 추가: `.granite/`, `*.ait`

## 4. 빌드

```bash
npx ait build      # → dist/ 빌드 + rmeng-quote.ait 아티팩트 생성 + deploymentId 발급
```
- `ait` 명령어: `token / build / deploy / migrate / init`. **`ait dev`는 없음.**
- 개발서버는 **`npx granite dev`** 로 띄움 (granite도 이 패키지의 bin). granite dev가 8081(런타임)+vite(5173)를 같이 띄움.
- RN 0.84.0 / 0.72.6 두 버전용으로 빌드됨.
- ⚠️ **`ait build`는 granite dev(개발서버)가 켜져 있으면 "시스템 리소스 부족"(Os code 1450)으로 실패함.** 빌드 전에 dev 서버를 끄고 포트(5173/8081)를 비울 것.

## 5. 테스트 방법

### ⚠️ Windows 사용자 주의 (우리 환경)
- **iOS 시뮬레이터 = Mac + Xcode 필요** → Windows에선 불가. iOS 실기기용 샌드박스는 현재 미제공.
- 따라서 Windows에선 **① 안드로이드 로컬 샌드박스** 또는 **② 콘솔 업로드 후 토스앱 QR 테스트** 중 선택.

### 방법 ① 안드로이드 로컬 샌드박스 (빠른 반복 개발용)
준비물: 안드로이드폰(또는 에뮬레이터), USB 케이블, `adb`(platform-tools. 실기기만 쓸 거면 Android Studio 풀설치 없이 adb만으로도 가능)

**adb 설치 (Windows, Android Studio 없이):**
```powershell
winget install --id Google.PlatformTools -e --accept-source-agreements --accept-package-agreements
```
- 설치 후 **셸 재시작해야 PATH 인식**. 안 되면 전체경로 사용:
  `C:\Users\User\AppData\Local\Microsoft\WinGet\Packages\Google.PlatformTools_Microsoft.Winget.Source_8wekyb3d8bbwe\platform-tools\adb.exe`

```bash
# 1) 폰: 개발자옵션 → USB 디버깅 켜기, USB 연결
adb devices                        # 기기 인식 확인

# 2) 샌드박스 APK 설치 (콘솔 '테스트앱(샌드박스)' 메뉴에서 APK 다운로드)
adb install -r -t apssintoss-debug.apk

# 3) 포트 연결 (USB라서 WiFi/IP 불필요 — localhost로 통신)
#    ⚠️ USB 재연결되면 reverse가 풀림 → 에러 나면 이 두 줄 다시 실행
adb reverse tcp:8081 tcp:8081
adb reverse tcp:5173 tcp:5173

# 4) 개발서버 실행 (vite 단독 아님! granite dev 로 8081+5173 같이 띄워야 함)
npx granite dev

# 5) 샌드박스 앱: 토스 비즈니스(개인)계정 로그인 → 앱 선택 → 토스 인증 → 스킴 intoss://rmeng-quote 입력
```
- 로그인은 **토스 비즈니스 가입한 개인 계정**으로 (공용계정 X). 토스 인증은 해당 계정 토스앱 푸시로.

**🔥 자주 막히는 지점 (실제 겪은 것):**
- **`net::ERR_EMPTY_RESPONSE` (5173)**: vite가 기본적으로 IPv6(`::1`)에만 바인딩되는데 adb reverse는 IPv4(`127.0.0.1`)로 접속해서 빈 응답이 옴. → **`granite.config.ts`의 `web.commands.dev`를 `'vite --mode toss --host 0.0.0.0'`로** 해서 IPv4에도 바인딩. (확인: PC에서 `http://127.0.0.1:5173/`가 200이어야 함)
- **8081에 아무것도 없음 → "앱 실행 중 문제 발생"**: `npm run dev`(vite만)로 띄우면 8081(granite 런타임)이 비어서 실패. 반드시 `npx granite dev`.
- **포트 충돌(vite가 5174로 뜸)**: 이전 dev 프로세스(좀비 node)가 5173 점유. → 5173/8081 점유 프로세스를 kill 후 재시작.
- **로그 확인**: `adb logcat -d` + granite dev 콘솔의 `RN LOG/WARN` 줄에 WebView 로딩 에러가 그대로 찍힘.

### 방법 ② 콘솔 업로드 + 토스앱 QR (가장 간단, 어떤 폰이든)
- `ait build`로 `.ait` 생성 → 콘솔에 업로드 → 콘솔 '출시하기'의 QR을 **실제 토스앱**으로 스캔해 테스트.
- Android Studio/adb/USB 전부 불필요. 단, 빌드 수정마다 재업로드 필요(핫리로드 X).
- **출시 요청을 보내려면 이 토스앱 테스트를 완료**해야 함.

### 샌드박스에서 테스트 안 되는 기능 (→ 콘솔 QR 토스앱에서 테스트)
| 기능 | 샌드박스 |
|------|---------|
| 토스 로그인 / 토스페이 / 인앱결제 | ✅ 가능 |
| **인앱 광고** | ❌ 불가 (토스앱 QR에서) |
| 분석 / 공유 리워드 / 가로 게임 | ❌ 불가 |

> 우리 1차 출시는 PDF 무료라 광고 테스트 불필요. 나중에 인앱광고 붙이면 샌드박스 말고 토스앱 QR로 검증.

### 디버깅
- Android: Chrome `chrome://inspect/#devices` → WebView inspect.
- iOS: Safari 개발자용 메뉴 → 기기 → 앱 → URL (Mac 필요).

## 8. 트러블슈팅 & 주의

- `npx ait init`이 "템플릿 선택"에서 멈춤(인터랙티브) → 기존 프로젝트는 **init 쓰지 말고 granite.config.ts 수동 작성**.
- `ait build` 시 chunk 500kB 초과 경고는 무시 가능(동작엔 문제없음). 추후 code-split 고려.
- 지원 OS 최소: Android 7 / iOS 16.
- master 브랜치 push = FastComet 웹사이트 자동배포. **토스 작업은 toss 브랜치에서**, 사이트 영향 주려면 master에 명시적 push.

## 9. 토스 SDK 자주 쓰는 기능 (web-bridge)

`import { ... } from '@apps-in-toss/web-framework'` 로 사용.

### 파일 저장 — 브라우저 다운로드(`<a download>`, `pdf.save()`)는 토스 웹뷰에서 막힘!
```js
import { saveBase64Data } from '@apps-in-toss/web-framework';
await saveBase64Data({ data: <순수 base64>, fileName: '견적서.pdf', mimeType: 'application/pdf' });
// 이미지: mimeType 'image/png'. data는 data:URI에서 ',' 뒤 base64만 넘김.
// jsPDF: pdf.output('datauristring') → ',' 뒤가 base64.  canvas.toDataURL('image/png') 동일.
```
- **웹/토스 분기**: `const IS_TOSS = import.meta.env.MODE === 'toss'` 로 감싸고, 토스 API는 `await import(...)`로 **동적 import** → 웹 빌드에선 vite가 자동 제거(웹사이트 영향 0). 우리 구현: `src/utils/pdfExport.js`.

### 그 밖에 쓸만한 것
- `openPDFViewer({ data, filename })` — base64 PDF를 네이티브 뷰어로 열기 (토스앱 5.261.0+).
- `share({ message })` — 네이티브 공유 시트.
- `getClipboardText()` / `setClipboardText()` — 클립보드.
- `fetchAlbumPhotos` / `fetchAlbumItems` — 앨범 사진 가져오기.
- 인앱결제/토스로그인/토스페이/인앱광고 등은 별도 예제(콘솔 생성 시 추가 가능).
